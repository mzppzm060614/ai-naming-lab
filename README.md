## 三、操作步骤

### 1. 安装依赖

```bash
npm install @supabase/supabase-js dotenv
```

### 2. 配置环境变量

项目根目录新建 `.env`（已被 `.gitignore` 忽略）：

```
SUPABASE_URL=你的supabase地址
SUPABASE_ANON_KEY=你的supabase匿名密钥

DOUBAO_API_KEY=你的火山方舟密钥
DEEPSEEK_API_KEY=
DASHSCOPE_API_KEY=
MOONSHOT_API_KEY=
```

用哪个模型就填哪个的密钥，其余留空即可。

### 3. 执行建表 SQL（阶段3）

1. 登录 Supabase，打开 **SQL Editor → New query**；
2. 粘贴 `supabase/schema.sql` 里的建表语句并执行。表结构与老师参考 SQL 一致：

```sql
create table name_history (
  id                bigint generated by default as identity primary key,
  user_requirement  text        not null,
  name_result       text        not null,
  model_name        text        not null,
  created_at        timestamp with time zone default now()
);
```

字段对应：`user_requirement` = 用户起名需求，`name_result` = 生成的名字方案，`model_name` = 使用的模型，`created_at` = 生成时间。

#### RLS 权限：调试期 vs 正式上线

- **调试期**：可以临时关闭 RLS（Supabase 后台 → 对应表 → Authentication → Disable RLS），或先不加 policy，方便接口先跑通。
- **正式上线**：不要长期关闭 RLS，也不要给 anon 角色无条件全表权限：
  - **方案 A（推荐，本项目结构）**：数据库访问只放在服务端接口，改用 `service_role` 密钥（service_role 绕过 RLS），浏览器前端不直连数据库；
  - **方案 B**：若必须用 anon 密钥让前端直连，按最小权限写 policy，例如只允许插入、只能读取自己的记录，不要用 `using (true)` 全开。

### 4. 启动预览

```bash
vercel dev
```

页面上会出现**模型下拉框**，选择四个模型之一，输入需求（例如：男孩、国风、简约），即可流式生成名字和寓意；历史记录会带上所用模型存入 Supabase。

## 五、阶段4：同步 GitHub + 部署 Vercel

### 1. 提交前安全检查

- 确认 `.env` 在 `.gitignore` 里（本项目已配好），密钥不会上传；
- 提交前 `git status` 里不应出现 `.env`、`node_modules/`。

### 2. 推送代码到 GitHub main 分支

在云终端项目目录执行（先在 GitHub 新建一个**空仓库**，不要勾选初始化 README）：

```bash
git init
git add .
git commit -m "feat: 多模型 AI 起名"
git branch -M main
git remote add origin https://github.com/<你的账号>/<仓库名>.git
git push -u origin main
```

> 若远程仓库已有提交，先 `git pull --rebase origin main` 再 `git push`。

### 3. Vercel 导入仓库并部署

1. 打开 <https://vercel.com/>，用 GitHub 登录 → **Add New → Project**；
2. 选中刚推送的仓库，点 **Import**；Framework Preset 选 **Other**，不用改构建命令；
3. 进入项目 **Settings → Environment Variables**，把本地 `.env` 里的变量逐个填上（Production / Preview 都勾上）：

| 变量名 | 说明 |
| --- | --- |
| `SUPABASE_URL` | Supabase 项目地址 |
| `SUPABASE_ANON_KEY` | Supabase 匿名密钥 |
| `DOUBAO_API_KEY` | 火山方舟密钥 |
| `DEEPSEEK_API_KEY` | DeepSeek 密钥 |
| `DASHSCOPE_API_KEY` | 通义千问密钥 |
| `MOONSHOT_API_KEY` | Kimi 密钥 |

4. 保存后重新 **Deploy**，完成后拿到公网域名，外网即可直接访问 AI 起名平台；
5. 以后改动代码 push 到 main，Vercel 会自动重新部署。

### 4. 上线后复核

- GitHub 仓库文件里搜不到任何密钥，`.env` 不在仓库中；
- 接口报 401 或提示缺变量时，先检查 Vercel 环境变量是否填全、是否在填完后重新部署过；
- 数据库权限按阶段3 的 RLS 说明收紧，不要长期开放匿名全表权限。

## 安全提醒

- 密钥只从环境变量读取，不写死在代码里；
- `.env` 不要提交到 GitHub；
- `modelConfigMap` 里只放地址和模型名，**不放密钥**；密钥运行时按 `envKey` 从环境变量取。
